## 出力スキーマ（厳守）

```json
{"subject": "...", "body": "..."}
```

または送信不可なら：

```json
{"subject": "SKIP", "body": "INSUFFICIENT_DATA: <理由>"}
```

## 必須構成（順序厳守・5ステップ展開）

提案メールは以下の **5ステップの流れ** で書く。「相手の現状観察 → 仮説提示 → ツールの存在紹介 → ツールが仮説を解決する筋道 → ご紹介のお時間のお願い」。一気通貫の **narrative（語り）** として読ませる。

```
1. 冒頭 自己紹介（1〜2文・短く）
　↓
2. 相手の現状観察（事実1点）
　↓
3. 仮説提示（〜ということがあるのではないか）
　↓
4. ドアマン・AI というツールがあるという紹介
　↓
5. そのツールは、仮説をこう解決できると思っている（解決の筋道）
　↓
6. ご紹介のお時間をもらえないか（CTA）
　↓
URL2本（サービスサイト → 予約）
　↓
署名
```

### 1. 自己紹介（1〜2文・短く）

「突然のご連絡失礼いたします。株式会社トラーナの志田と申します。」程度で十分。冗長な自己紹介は避ける。

### 2. 相手の現状観察（事実 **3点以上** を織り込んで厚く書く）

**ここは提案の説得力の根幹。1文で済ませてはいけない。**

`hook_context`／`notes`／`enriched` 情報から、相手企業の現状を **3点以上の事実** で立体的に描写する。
事実観察は **事実として淡々と** 書く（観察できる情報なので断定OK）。**2〜3文、合計100〜180字程度** の厚みを目安に。

**織り込むべき事実カテゴリ（ICP優先順に：A → B → C → D → E から該当する複数を組み合わせる）：**

1. **A: 採用シグナル** — IS／SDR／新規開拓営業／FS／マーケなどの **求人内容を具体的に**（職種名・複数併記・新卒中途の別など）
2. **B: 成長シグナル** — 上場区分（TSEプライム／スタンダード／グロース）、直近のリリース内容（新サービス／資金調達／拠点拡大／上場準備）、店舗・拠点数、グループ規模
3. **C: 商材／事業特性** — 主力事業領域（SaaS／広告／人材／コンサル／士業／製造販路）、顧客タイプ、商談獲得の事業構造（BtoB／代理店経由／直販）
4. **D: 外注痕跡** — 営業代行／リスト購入／MAツール／派遣SDR等の利用が示唆される表現
5. **E: 情報管理** — 機微情報を扱う業種特性、クラウドSaaS導入ハードル

**書き方の型：**

```
[A の事実] + [B または C の事実] + [事業構造／フェーズの観察]
　↓ ここまでで2〜3文、100〜180字
→ Step 3 の仮説へ自然につなぐ
```

**❌ NG（薄すぎる現状観察）：**
> ❌「貴社採用ページで、インサイドセールス・Web広告営業の中途採用を複数拝見しました。」
>
> → 求人を見たという1点だけ。事業文脈・成長フェーズ・商材特性に触れていない。

**✅ OK（厚い現状観察）：**
> ✅「貴社はTSEスタンダード上場の Web マーケティング／SaaS 企業として、SEO・AI最適化・Web広告などの BtoB ソリューションを継続展開されていらっしゃいます。直近の採用ページでは、インサイドセールスと Web 広告営業の中途採用を複数職種で同時公開されており、商談獲得チャネルの拡張フェーズに入っていらっしゃるかと拝見しております。」
>
> → 上場区分 → 主力事業領域 → 採用詳細 → 事業フェーズの推察 まで4点が織り込まれている。

**Step 2 → Step 3 への接続：**
Step 2 の最後の事実から、Step 3 の仮説へ「そうしたなかで、〜という局面があるのではないか」と自然な流れで繋ぐ。Step 2 と Step 3 が **論理的に連動** していること。

### 3. 仮説提示（〜ということがあるのではないか）

ステップ2で挙げた相手の現状から、自然な流れで **仮説の語尾** で課題仮説を提示する。
ステップ2と仮説は意味的に繋がっていること（採用しているから〜、成長しているから〜、外注しているから〜）。

語尾例（必ず仮説形）：
- 「〜ということがあるのではないかと拝察しております」
- 「〜という状況が背景にあるのではないかと感じております」
- 「〜の余地があるのではないかと拝察しております」
- 「〜の論点になり得るのではないかと見受けられます」

**断定禁止**：「〜が課題である」「〜を取りこぼしている」「〜が眠っている」「〜に困っているはず」

仮説の典型例：
- 採用シグナル → 「IS／SDRの採用と立ち上がりまでに一定の時間を要し、新規開拓の手数が一時的に不足する場面があるのではないか」
- 成長シグナル → 「新サービス／拠点拡大の局面でリードの母集団を一段増やしたい一方、固定費の上振れは抑えたいご事情があるのではないか」
- 商材適合 → 「貴社の事業特性上、問い合わせフォーム経由の新規開拓が一定ボリュームで発生し、人手で回している部分が残っているのではないか」
- 外注痕跡 → 「営業代行／MAツール等の外注費が固定費化しており、CAC構造の見直し余地があるのではないか」
- 情報管理 → 「機微情報の取り扱い上、クラウド型SaaSの導入ハードルが高く、社外にデータを出さない仕組みが望ましいのではないか」

### 4. ドアマン・AI というツールがあるという紹介

「弊社では『ドアマン・AI』という自社サーバー設置型のローカルAI営業エージェントをご提供しております。」
のように、まず **存在を紹介** する。差別化点はステップ5でぶつける（ここでは並べ過ぎない）。

### 5. ツールが仮説を解決する筋道（解決マッピング）— **最重要セクション**

ここが提案の核心。**機能を列挙して終わってはいけない**。ステップ3の仮説に対し、ドアマン・AIの差別化機能（①ローカル型・月額なし／②リスト作成〜送信〜レポートまで自律運用・月1,500通無人／③データ社外不出／④各種AI接続可能／⑤オンサイト導入対応）から **2点以上** を選び、**「この機能がゆえに、その仮説の問題がこう解ける」** という因果ロジックを言語化する。

**機能訴求の比重を高める：** 単に「便利です」ではなく、各機能の **具体的な動作・スペック・体験** を一行で挟むこと（例：「リスト作成 → 問い合わせフォーム送信 → レポートまでを AI エージェントが自律的に処理し、月最大1,500通まで人を介さず回せます」「各種AIモデルに差し替えて接続でき、社内承認済みLLM運用にも適合」「環境準備が難しい場合はオンサイトでのインストールにも対応」）。

**書き方のルール（厳守）：**

1. 各機能には必ず **「〜ので／〜により／〜ため／〜の結果」** など因果接続詞で「仮説の問題がこう解消される」筋道を添える
2. 機能の言い換え（無人運用→人を採らずに手数が増える、月額0円→撤退コスト0、社外不出→セキュリティ承認を取らずに導入可）の **意味の翻訳** を入れる
3. **「貴社の場合」「今回のケースですと」** など、ステップ3の仮説に呼応する一言を必ず冒頭に置く
4. 単なる機能箇条書きや「〜できます」だけの文は禁止。**仮説→機能→なぜ仮説が解けるか** の3点セットになっていること

**因果説明テンプレ（必ずこの構造で書く）：**

> 貴社の場合、〔仮説の状況〕でいらっしゃるかと拝察しております。
> ドアマン・AI は〔機能A〕のため、〔機能Aが仮説をどう解くかの説明〕。
> 加えて〔機能B〕により〔機能Bが仮説をどう解くかの説明〕。
> こうした構造から、〔仮説の問題〕に対し〔具体的にどう効くか〕の選択肢として
> お役に立てる余地があるのではないかと考えております。

**仮説別・因果説明の具体例（参考にして引き写すこと）：**

【仮説A：IS／SDR採用の立ち上がり時間で手数不足】
> 貴社の場合、IS／SDRの中途採用と立ち上がりまでに数か月を要し、その間に新規開拓の手数が滞る局面があるかと拝察しております。ドアマン・AI は問い合わせフォームへの新規送信を月最大1,500通まで **人を介さず** 走らせられるため、採用が決まる前から **採用1名分相当の新規接触量** を即日確保いただけます。加えて買い切り型のため、採用完了後に運用を絞っても月額の固定費は発生せず、補完用途と本格運用の **両方の使い方** に耐える設計になっております。

【仮説B：成長フェーズで母集団を増やしたいが固定費は抑えたい】
> 貴社の場合、新サービス／拠点拡大の局面でリード母集団を一段増やしたい一方、固定費の上振れは抑えたいご事情があるのではないかと拝察しております。ドアマン・AI は **買い切り型（月額0円）** のため、増額分は導入時の一回限りで、リード獲得量を増やしても **月次コストはゼロ** に張り付きます。さらに月最大1,500通の無人運用ができるため、人員増を伴わずに **手数の上限だけを一段引き上げる** 形で母集団拡大に効きます。

【仮説C：商材適合・フォーム新規開拓が一定ボリュームで発生】
> 貴社の事業特性上、問い合わせフォーム経由の新規開拓が一定ボリュームで発生し、人手で回している部分が残っているのではないかと拝察しております。ドアマン・AI は月最大1,500通まで無人で送信を回せるため、**現状の人手作業を機械側に寄せた上で、人の時間はリード対応や商談に再配分** いただけます。買い切り型なので運用コストは導入時の一回限り、送信量を増やしても **CACの限界費用がほぼゼロ** で済む構造です。

【仮説D：営業代行／MAツール等の外注費が固定費化】
> 貴社の場合、営業代行・派遣SDR・MAツール等の月額費用が固定費化しており、CAC構造の見直し余地があるのではないかと拝察しております。ドアマン・AI は **買い切り型（保守任意月5万円）** のため、月次の代行費を一括で **資本支出化** することで、月次CACを構造的に下げられます。送信量を上げても従量課金は発生しないため、外注の **置換あるいは併用** どちらの設計でもコスト天井が見えやすくなります。

【仮説E：機微情報の取り扱い／クラウド型SaaS導入ハードル】
> 貴社の業務領域では機微情報の取り扱いが厳しく、クラウド型のSaaS導入はセキュリティ承認のハードルが高いのではないかと拝察しております。ドアマン・AI は **自社サーバーへの設置型** で送信先データ・リードデータが **社外に一切出ない** 設計のため、外部にデータを預けない前提でフォーム送信の自動化を導入いただけます。情報統制要件と新規開拓の自動化を **両立** させる選択肢としてお役立ていただける余地があるのではないかと感じております。

**❌ NGな解決マッピング例（こう書いてはいけない）：**

> ❌「弊社『ドアマン・AI』は自社サーバー設置型のローカルAI営業エージェントです。問い合わせフォームへの新規送信を月最大1,500通まで無人で運用し、買い切り（月額0円）で手数を補完できます。」
>
> → 機能を並べて「補完できます」と言い切るだけで、**なぜ／どう補完できるかの因果説明がゼロ**。これは禁止。

**✅ OKな解決マッピング例：**

> ✅「貴社の場合、IS／SDRの中途採用がそろう前の数か月で新規開拓の手数が一時的に薄くなる局面があるかと拝察しております。ドアマン・AI は問い合わせフォーム送信を **人を介さず** 月最大1,500通まで運用できるため、採用が決まる前から **人員1名分相当の新規接触量** を即日確保できます。加えて買い切り型のため、採用完了後に絞っても月次の固定費は残らず、立ち上がり期の補完と本格運用の **両方の使い方** に耐える設計です。」
>
> → 仮説に呼応した冒頭、各機能の **「〜のため、〜できる／残らない」** の因果接続、機能の **意味の翻訳**（人を介さず＝採用前から手数確保／買い切り＝撤退コスト0）が揃っている。

## 字数対応

- フォームの `max_chars` が **400字以下** → 約400字版（上記構成を全て圧縮）
- `max_chars` が **〜2,000字** → 約500字版（課題仮説と差別化説明をやや展開）
- それ以上余裕がある場合も、**500字を超えない**。冗長な提案メールは読まれない。

## URL フォールバック（フォーム要件で URL が弾かれる場合）

- **2本ともURL弾かれる** → サービスサイトURL1本のみ＋「ご返信をいただけますと予約URLをお送りいたします」
- **字数が極端に短い**（300字以下） → 予約URLを削り、サービスサイトURLのみ残す
- **URL全面禁止フォーム** → URL全削除のうえ「『ドアマンAI』で検索ください。詳細はサービスサイトをご覧いただけます。ご返信をいただけますと無料相談のご案内をお送りいたします。」と返信誘導

## SKIP判断

`category` が以下なら `subject: "SKIP"`：
- `b2c_only` — B2C顧客フォームのみで B2B提案先として不適切
- `iframe` — 第三者ホスト iframe で送信先が不確実
- `site_closed` — 合併・閉鎖済み

加えて、以下も SKIP：
- 営業自動化／フォーム送信／営業代行の **直接競合** と判断される場合
