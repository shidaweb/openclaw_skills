# Doorman — Slack コマンド一覧（@OpenClaw に投げる）

Slack で **`@OpenClaw` に続けて自然言語**で投げます。以下は代表例で、表現は柔軟に解釈されます
（厳密な構文ではありません）。`<...>` は適宜置き換えてください。

---

## 起動・送信

| こう言う | 何が起きる |
|---|---|
| 「EdTechで売上50億〜の企業を10社、フォームに送って」 | リスト作成→文面生成→送信まで一気通貫 |
| 「キャンペーン回して」 | 既定設定でキャンペーン実行 |
| 「<条件>で10社、送らずにドラフトまで作って」 | 文面生成まで（送信しない）。確認用 |
| 「フォーム構造取らずにドラフトまで」 | enrich を省略して下書きのみ |
| 「<会社>の1番送って」「1番送って」 | 指定ドラフトを送信（2段確認あり） |
| 「全部止めて」 | 実行中の送信を停止 |

## 自律モード（人にいちいち確認しない運用）

| こう言う | 何が起きる |
|---|---|
| 「自律モードにして」「全部任せる」 | 自律運用へ。初回は「リスト＋サンプル文面」を提示して**承認待ちで停止** |
| 「承認」「OK進めて」 | 事前承認待ちを解禁 → 以降は確認なしで全件自動送信 |
| 「自律状態どう？」 | 現在のモード・承認状態・自動送信/スキップ件数を返信 |
| 「自律やめて」「戻して」 | 1件ずつ承認する supervised モードへ戻す |

## ブロッカー対応（送信ボタン未検出・確認待ち 等）

| こう言う | 何が起きる |
|---|---|
| 「保留どれ？」「詰まってるのある？」 | 保留中ブロッカーを**候補ボタン付き**で一覧 |
| 「詰まった分を片付けて」 | 別プロセスで深掘り再試行（リゾルバ起動） |
| 「<id> skip」 | その案件をスキップ（記録して対象外に） |
| 「<id>進めて」 | （supervised時）確認待ちの案件を手動再開 |
| 「<会社>の業界はその他で」 | 想定外フォーム項目への回答（needs_attention 解決） |

## ドラフト品質の調整

| こう言う | 何が起きる |
|---|---|
| 「ドラフト見せて」 | 生成済み文面を表示（送信しない） |
| 「丁寧モードで」「refineありで」 | 推敲パスを入れて品質を上げる |
| 「refineなしで」 | 推敲なしで速く |
| 「コスト抑えてrefine」 | 品質が低い文面だけ推敲 |
| 「もっと絞って」 | ターゲットペルソナを調整して再生成 |

## 進捗・稼働確認

| こう言う | 何が起きる |
|---|---|
| 「生きてる？」「ping」「status」 | 稼働・heartbeat・要対応件数を即答 |
| 「進捗どう？」 | 現在の処理状況（何件目・stage）を要約 |

## 実績・レポート

| こう言う | 何が起きる |
|---|---|
| 「今月何件送った？」「今週/先月/累計の送信サマリ」 | 会社・内容・試行/成功/失敗・失敗理由を要約 |
| 「送信ファネル見せて」 | open→送信→検証の歩留まりを表示 |
| 「品質ポイント教えて」「draft品質どう？」 | 文面品質の傾向をレポート |
| 「needs_attentionまとめて」 | 要対応案件を集約 |
| 「<会社>のトレース見たい」 | その案件の詳細ログ |
| 「今週の改善ポイント3つ」 | 改善提案を要約 |
| 「送信履歴」「何件送った？」 | これまでの送信実績 |

## リスト・ターゲット

| こう言う | 何が起きる |
|---|---|
| 「<条件>で10社リストアップして」「リスト作って」 | 条件に合う企業を抽出してターゲット化 |
| 「<会社>をターゲットに追加して」 | 個別追加 |

## セットアップ・運用

| こう言う | 何が起きる |
|---|---|
| 「新しいbrief作って」「セットアップして」 | Slack 対話で発信者・商材・ターゲットを質問（onboarding） |
| 「ログ掃除して（90日）」 | 古いログを整理 |

---

### 補足

- これらは**自然言語トリガー**で、言い回しの揺れは解釈されます（厳密なコマンド構文ではありません）。
- 軽量な問い合わせ（「ping」「生きてる？」「進捗どう？」）は **5秒以内に即答**します。
- 自律モードでは、最初の「承認」以降はブロッカーも自動でスキップ/迂回し、**完了報告まで基本沈黙**します。
- チャンネルが brief にバインド済みなら、毎回どの発信者人格で動くかの確認は省略されます。
